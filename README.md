# AniLink

AniLink is a PHP and MySQL application for local agricultural listings, buyer inquiries, and sourced market-price information. The existing single-page frontend and visual design are retained; database-backed behavior is provided by `backend/api.php`.

## Requirements

- XAMPP with Apache, MySQL, and PHP 8.0 or later
- PHP extensions `pdo_mysql`, `fileinfo`, and `mbstring`

## Run with XAMPP

1. Copy the project folder to `C:\xampp\htdocs\AniLink`.
2. Start Apache and MySQL in the XAMPP Control Panel.
3. Open `http://localhost/phpmyadmin/`, import `database/anilink_db.sql`, and confirm the `anilink_db` database appears. For an existing installation, make a database backup first, then import `database/migrations/001_inquiry_messaging.sql` into `anilink_db`. The migration is safe to rerun and creates conversations for existing inquiries.
4. The default local connection is host `localhost`, database `anilink_db`, username `root`, and an empty password. To use different credentials, set `ANILINK_DB_HOST`, `ANILINK_DB_NAME`, `ANILINK_DB_USER`, and `ANILINK_DB_PASSWORD` in the Apache/PHP environment, then restart Apache.
5. Create the first administrator from a command prompt:

   ```text
   cd C:\xampp\htdocs\AniLink
   C:\xampp\php\php.exe backend\create_admin.php "AniLink Admin" admin@example.com "+63 900 000 0000" Boac
   ```

   Enter the administrator password when prompted. Public registration only permits Farmer and Buyer roles.
6. Seed the demonstration farmer's 23 product listings (this is safe to run repeatedly; an existing farmer account's password and profile are preserved):

   ```text
   cd C:\xampp\htdocs\AniLink
   C:\xampp\php\php.exe backend\seed_demo_farmer.php
   ```

## Backend overview

- `backend/config/database.php` creates a reusable PDO/MySQL connection.
- `backend/helpers/functions.php` centralizes sessions, authorization, CSRF checks, product validation, and image uploads.
- `backend/api.php` exposes JSON actions for registration, login/logout, marketplace products, farmer listings, inquiries, private conversations, messages, notifications, market prices, and administrator management.
- `database/anilink_db.sql` creates the relational schema, indexes, constraints, and six clearly identified illustrative price records.
- `database/migrations/001_inquiry_messaging.sql` upgrades existing inquiries into private conversations and backfills their first messages.
- `backend/seed_demo_farmer.php` idempotently updates the farmer's sample listings without overwriting an existing account's password or profile.
- `backend/create_admin.php` is a CLI-only first-admin setup command.
- `js/backend.js` connects the existing interface to the API while retaining the existing stylesheet and navigation.

All database writes require the session CSRF token. Sessions use HTTP-only, SameSite=Lax cookies. Database errors are logged to the PHP error log; API clients receive a generic error instead of internal details.

## Verification checklist

| Test | Expected result |
|---|---|
| Register a Farmer and Buyer, then register an existing email again | Both valid accounts are stored; duplicate email is rejected. |
| Sign in and open another role's dashboard/API operation | User sees their own workspace; disallowed operations return 403. |
| Add, edit, and deactivate a Farmer listing with and without a photo | The product is saved in MySQL; invalid images are rejected; only its owner can edit/deactivate it. |
| Search, filter, and sort marketplace products | Results match the selected database filters and ordering. |
| Submit an inquiry as a Buyer | An inquiry with product, buyer, farmer, subject, message, optional quantity, status, and timestamp is stored. |
| Reply to an inquiry as its Farmer | The message is stored in the same private conversation, the Buyer gets an unread notification, and a pending inquiry becomes Responded. |
| Open Messages as either participant | Conversation history loads, unread messages are marked read, and new messages are polled without a page reload. |
| Open another user's conversation ID | The API returns not found and exposes no message content. |
| Mark a notification read | The notification's read state is saved for its owner only. |
| Update that inquiry as its Farmer | The Farmer sees the inquiry and the Buyer sees the updated status and notification. |
| Manage accounts, listings, and market prices as Administrator | Counts reflect database records; account/listing statuses and price CRUD persist. |
| Submit a state-changing API request without its CSRF token | The request is rejected with HTTP 403. |
| Open public market-price information | Each price shows its source and recorded date; illustrative values are marked as samples. |

## Limitations

- The included market-price rows are copied from the original mock UI and are explicitly marked illustrative and unverified. Replace them only with verified data and accurate source/date information.
- Password recovery, email delivery, purchase processing, and official price-feed integrations are not implemented. Messaging uses five-second AJAX polling, not WebSockets.
- Deployments beyond local XAMPP should use HTTPS, a least-privilege database account, regular backups, and server-level upload limits.
